Features

Every stage of a tender, handled in one place

Amit Automation Suite is organised into modules that share a single database, a single set of master lists and a consistent interface. Below is what each module does today, and what is still in development.

01 — Tender Search

Find the tenders worth bidding on

Searching happens in two places: outward, against the Central Public Procurement Portal, and inward, across the tenders you already hold.

CPPP portal search

Available

The scraper attaches to your own Chrome or Edge browser, opens the portal's advanced search and fills the criteria from a saved search profile. You solve the CAPTCHA and press Search yourself; the scraper then reads the paginated result table and opens each detail page to extract its fields.

  • Search profiles stored in the database and reused run to run
  • Organisation, tender type, value criteria and date conditions all configurable
  • Detail pages read label by label, then mapped onto tender fields
  • Every candidate classified New, Duplicate or Changed before import
  • You choose which rows to import — nothing arrives unreviewed

Search inside your data

Available

A single search box runs across the tender record. Frequently used queries are saved as search cards — a card is simply a stored query, so a card and a free-text search always return the same answer for the same criteria.

  • Free-text search across registered tender fields
  • Saved search cards with keywords, date windows and conditions
  • Live result count on each card
  • Per-column filters and multi-sort in every grid

02 — Tender Management

A working record for every tender

Tenders move through defined stages, and the grid that displays them behaves the way a spreadsheet does — without the fragility of one.

Import from Excel

Pick a workbook, pick a worksheet, and map its column headers onto tender fields. Known headers are suggested automatically, so a recurring import format only has to be mapped once.

Stages and promotion

A tender sits in the Import stage while it is being assessed and is promoted to Master once its EMD payment has succeeded. One rule decides that promotion, so the Import and Master grids can never disagree.

Grids that stay how you left them

Show, hide, reorder, resize and freeze columns per grid. Layouts are saved automatically and restored on the next launch, per screen.

Rules, not hard-coded logic

Categories are assigned by keyword rules you maintain. Row and field highlighting, days-left thresholds and process statuses are all configurable tables — no values are fixed in the program.

Custom fields

An administrator can add fields to the tender record itself. They behave like every other field — searchable, mappable in imports, usable as document placeholders.

Dashboard

Total, today's, upcoming and overdue tender counts; EMD committed, refund pending, refunded and held balances; plus zone-wise and stage-wise breakdowns and recent activity.

03 — EMD Tracking

Earnest money, from commitment to refund

EMD is money that leaves the business and is expected to return. The suite tracks both directions and keeps the tender's own EMD figure separate from whatever the bank actually charged.

Assisted EMD payment

Available

The EMD run attaches to your browser and works alongside you: it watches which page you have reached, fills the parts it is responsible for, reads back what the portal shows, and goes quiet again. Every selector it uses is held in one versioned registry, so a portal change is a configuration update rather than a rewrite.

  • Starts only on an explicit action, never on screen navigation
  • Never fills a CAPTCHA and never clicks Login, Search or Submit behind one
  • Pause, resume and stop at any point during a run
  • Credentials never appear in logs, screenshots or error text

Receipts and refunds

Available

Payment receipts are read by the document parser and offered against the tenders they most likely belong to, rated best, average or poor. Refunds are found in bank statements and are proposed the same way.

  • Suggestions are ranked and explained — never linked automatically
  • A receipt can add a missing value but can never blank an existing one
  • A tender stays unmatched until a person presses Link
  • Applied and skipped fields both recorded in the audit log

Dedicated EMD Management and EMD Refund screens are placeholders in the current release. EMD figures, balances and zone-wise breakdowns are available today on the Dashboard, and EMD payment, receipt capture and refund matching all work through the modules described above.

04 — Document Generation

Your templates, filled from your data

The document engine works from Word templates you already use. Placeholders are resolved against the tender, your company profile, the company's bank details and the application's settings.

Placeholder registry

Every tag a template can contain is registered once and mapped to a source field. Templates stay plain Word documents — there is nothing to install into Word.

Validation before generation

A pre-flight pass marks each tag Resolved, Missing Value or Not In Registry, and shows the resolved text, so a document with a blank in it is caught before it is written.

Batch wizard

Generate across many tenders and many templates in one run. Each tender-and-template combination reports its own status, so a single missing value does not stop the batch.

Naming patterns

Output folders and file names are built from patterns you define in settings, so generated paperwork files itself consistently without anyone renaming anything.

Tender document downloader

Downloads a tender's ZIP and PDF documents from the portal through your own browser, moves them into the tender's folder and records the path on the record. It checks first whether the documents are already held or the tender has closed.

Company and bank details

Company master data and bank accounts are held once and feed both the documents and the reconciliation side, so a change of address or account is made in exactly one place.

05 — Tender Submission Helper

Designed, approved, not yet released

This module has an approved architecture but no released implementation. It is described here so the intended scope — and its limits — are clear.

What the submission helper is intended to do

In development

The design has the automation prepare the portal session and take responsibility for one action — uploading the technical-cover documents — and then stay in monitor mode until the acknowledgement PDF has been downloaded, renamed against the tender and written back to the record. The bid itself remains the operator's to make.

  • Portal login details held in the company master, encrypted with Windows DPAPI, masked in the interface and filled only on a verified portal login page
  • CAPTCHA, Proceed, digital signature, Freeze and the final Submit remain operator-only actions and are not automated
  • The BOQ and the submission itself stay with the operator
  • Acknowledgement filed automatically against the correct tender

This module is not part of the current release. Everything above describes an approved design, not shipped behaviour.

06 — Financial Operations

Bank statements, matched to tenders on evidence

Statements are imported, cleaned of overlap, and compared against tenders using identifiers first and amounts second — because a round EMD figure matches every same-value transfer in an operating account.

Statement import

Available

Everything bank-specific is a configuration row rather than program logic, so supporting another bank is a new profile, not a new build. PDF columns are located by position from the statement's own header row, which keeps a withdrawal from being read as a deposit.

  • PDF and Excel statements, multiple banks and multiple accounts
  • Consolidated files that switch account part-way through are handled
  • Genuine ambiguity is reported rather than guessed
  • Password-protected statements open from an encrypted stored password, or prompt

Deduplication and matching

Available

Downloads overlap by design, so duplicates are removed per transaction rather than per file — reference or UTR first, then a fingerprint, then a near-duplicate check, always scoped to one account.

  • Debits treated as payments, credits as refunds — never confused
  • A refund must carry a reliable identifier before it can be proposed
  • A refund dated before its payment is rejected outright
  • Bank charges are reported alongside the EMD, never merged into it
  • Proposals are marked for review; a link exists only once confirmed

Excel export

Available

Export the current view or a whole account to a workbook with separate Summary, Transactions, Reconciliation and Exceptions sheets — the exceptions sheet being the one that shows what still needs a decision.

Indian number formatting

Available

Money is displayed throughout in Indian digit grouping. Values sent to portal input fields are written as plain digits, so formatting never travels where it should not.

Underneath

Supporting capabilities

Infrastructure the modules above rely on, and which shapes what the suite can be asked to do next.

Document parsing and OCR

Text is taken from a PDF's own text layer when that layer is usable, and the page is rendered and read optically when it is not. Two OCR engines run and are cross-checked against one another, and disagreement on an important field is flagged for a person rather than silently resolved.

  • Reading order rebuilt from page geometry, so labels stay with their values
  • English and Hindi / Devanagari, including mixed-script pages
  • Digits in any script normalised before a parser sees them
  • Nothing to install — both engines ship inside the application

Google Calendar sync

Optional one-way sync of tender dates into a Google Calendar you choose, so deadlines appear where you already look for them. Event titles, descriptions and reminders are built from patterns you configure.

  • Off until you sign in and choose a calendar — there is no default
  • Only tenders you opt in are ever sent
  • One-way: the calendar never writes back into your records
  • Sign out at any time; the stored token is deleted

Configuration over code

No company name, bank name, portal label, category, template path or amount is fixed in the program. They all resolve at run time from master lists, settings and rule tables an administrator maintains — which is why the suite can follow a portal or a process change without a new build.

  • Master lists for banks, firms, departments and statuses
  • Settings grouped by area, each with its own defaults
  • A field registry that discovers candidate fields rather than listing them
  • Administrator-only screens behind a password, unlocked once per session

Security model

Secrets are encrypted with Windows DPAPI under your own account, so a copied database file does not open them elsewhere. Sensitive values are kept out of logs, screenshots and exception text, and error messages from external services are stripped before display.

Interface

Light and dark themes that persist across restarts, a sidebar you can collapse and reorder to match how you work, and right-click actions available directly on grid rows.

Audit log

Changes applied through the automated paths are recorded with the field, the value and the decision taken — including fields an operator was offered and chose not to apply.
