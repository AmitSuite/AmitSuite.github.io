About

Built from the way the work is actually done

Amit Automation Suite grew out of a real tender operation and the spreadsheet system that used to run it. Every rule in the product exists because a real document, a real portal page or a real bank statement made it necessary.

The product

A single application for the tender lifecycle

Amit Automation Suite is a Windows desktop application for government construction tender management, developed for Aanya Enterprises. It covers the lifecycle from discovery through to award and refund: finding tenders on the Central Public Procurement Portal, holding the tender record, generating documents, paying and tracking earnest money deposits, and reconciling that money against the bank.

It replaces a long-running Excel and VBA system. The goal was not to change how the work is done — it was to keep the workflow the operator already knew while removing the fragility of a spreadsheet: no broken formulas, no lost column, no second copy of the truth. Records live in a single local database, and every module reads the same one.

The suite is delivered one module at a time, verified between phases. Modules that are designed but not yet released are labelled as such throughout this site rather than being described as though they exist.

Principles

The rules the product is built on

These shape every module, and they are the reason the suite behaves consistently across screens that were built years apart.

Nothing is hard-coded

No company name, bank, portal label, category, template path or amount is written into the program. Everything resolves at run time from master lists, settings and rule tables an administrator maintains — which is why a portal or process change is usually a configuration change, not a new release.

The operator is in charge

Automation assists a person; it does not stand in for one. The browser belongs to the operator, human checkpoints stay human, and any run can be paused or stopped without leaving a record half-written.

Suggest, then wait

Where the suite infers something — which tender a receipt belongs to, which transaction is a refund — it produces a ranked proposal with its reasoning shown, and stops. A record changes only when a person confirms it.

Evidence before arithmetic

Matching leads on identifiers and uses amounts only to corroborate, because a round EMD figure matches every same-value transfer in a working account. Facts that cannot be true — a refund dated before its payment — are rejected outright rather than scored.

Never lose what is already known

An automated step can fill a field that is empty. It can never blank a value the record already holds, and it never overwrites a decision a person made by hand.

Tested against real documents

Parsing is developed against genuine receipts and statements, not clean fixtures. Their awkwardness — consolidated multi-account files, collapsed empty columns, unreadable text layers, password protection — is the point of the exercise.

Technology

What it is built with

Deliberately conventional choices, so the application stays fast, starts cleanly and needs nothing installed alongside it.

Platform
.NET 8 (long-term support)
Interface
WPF, with light and dark themes
Database
SQLite, single local file, write-ahead logging
Documents
Open XML for Word generation, ClosedXML for Excel
PDF and OCR
PdfPig for text extraction; PaddleOCR and Tesseract cross-validated, both shipped inside the application
Browser work
Playwright, attaching to the operator's own Chrome or Edge
Calendar
Google Calendar API, optional and opt-in

Requirements

What you need to run it

A standard Windows workstation. There is no server to install and no online account to create.

Operating system
Windows 10 version 2004 (build 19041) or later, 64-bit
Browser
Google Chrome or Microsoft Edge, for the portal modules
Internet
Needed only for portal work and, if enabled, calendar sync. The rest of the application works offline
Word
Not required to generate documents — templates are read and written directly
OCR setup
None. Both OCR engines and their language data ship with the application
Data location
A single database file in your own Windows user profile

Who builds it

Developed and maintained by Amit Jain

Amit Automation Suite is designed, built and supported by Amit Jain for Aanya Enterprises. Development is phased and driven by the operation it serves — each module is specified, built and verified against real work before the next one begins.
